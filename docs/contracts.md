# Internal contracts
Python import root = repository root. Python 3.12; backend is a package.
Market Bar dataclass: exchange:str, symbol:str, timeframe:str (Pine, e.g. "1", "15", "60", "30S"), start:int (UTC ms), end:int (exclusive UTC ms), open/high/low/close/volume:float, confirmed:bool=True, received_at:int|None=None. Engine accepts dict bars as well.
Instrument metadata: exchange, symbol, tick_size, base_coin, quote_coin, status, contract_type, launch_time.
Engine interface backend.engine.runtime.PineEngine(symbol, timeframe, tick_size=0.01, parameters=None).update(bar:dict, contexts:dict|None=None, realtime=False) -> snapshot dict. contexts maps "EXCHANGE:SYMBOL|TF" -> list[bar dict] chronological. Bybit symbol context uses "BYBIT:BTCUSDT.P"; BTC context "BINANCE:BTCUSDT.P". Missing context never fabricated.
Snapshot canonical fields: exchange, symbol, timeframe, price, bar_start, event_time, received_at, confirmed, setup_generation_id (str), action, fsm, direction (LONG/SHORT/NONE), candidate_path, trigger_path, risk_path, formation, execution, geometry, context, level, approach, exhaustion, mae, avg_setup, continuation, btc_shock, sl, t1, rr, blockers:list, gates:dict, signals:list[str], metrics:dict (all Pine variables), data_health, parity_status, engine_version, pine_source_hash, parameter_set_id. Values unavailable are null, no synthetic scores.
Engine export_state()/restore_state(payload) for JSON checkpoints. Engine source execution is exact-order interpreter, parity remains UNVERIFIED until external TradingView export supplied.
API envelopes: GET setups returns {items: Snapshot[], total:int}; GET detail returns Snapshot; history {items:Snapshot[]}; GET signals/instruments/research/alerts/rules/alerts/deliveries {items:[]}; GET parameters {id,values,schema}; PUT parameters {values:{...}}. GET health {status,services,...}; GET parity {status,metrics:[],signals:[],...}. GET bars /api/setups/{symbol}/{timeframe}/bars -> {items:[Bar]}; GET events /api/setups/{symbol}/{timeframe}/events -> {items:[]}. WS /ws/setups sends {type:"snapshot", data:Snapshot}. Alert rules {id,name,enabled,conditions:{op:"AND",conditions:[{field:"avg_setup",op:">=",value:70}]},mode:"realtime"|"confirmed",frequency:"once_per_bar"|"once_per_generation"|"first_occurrence"|"repeat",cooldown_seconds,template}. POST /api/alerts/rules/test {conditions:...}; POST /api/alerts/test-telegram explicit user click, never automatic in tests.
Parameters schema will be generated to reference/inputs.json: array of {name,type,default,title,minval,maxval,options,group,tooltip}. API/worker load via backend.engine.parameters module.
