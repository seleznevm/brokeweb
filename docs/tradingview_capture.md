# Как передать внутренние оценки и intrabar из TradingView

Обычная выгрузка графика в CSV — правильный способ получить исторические значения. Однако она содержит только опубликованные индикатором ряды, а не все его переменные. Подготовлены три диагностические копии **Scalping_SMA 1.15.2**. Они не предназначены для версии 1.16.5. Исходный файл 1.15.2 сохранён без изменений.

Копии проверены локальным парсером проекта. **Компиляция на TradingView ещё не подтверждена.** Если Pine Editor покажет ошибку, передайте её текст, номер строки и имя копии: успешный разбор нашим парсером не заменяет проверку компилятором TradingView.

## 1. Внутренние оценки: CSV графика

1. Откройте обычные свечи `BYBIT:ETHFIUSDT.P`, таймфрейм **30 минут**. Можно использовать другой инструмент из прежних выгрузок, но укажите его и таймфрейм. Не используйте Heikin Ashi, Renko или пересчитанный/составной символ.
2. В Pine Editor создайте два личных индикатора, полностью скопировав соответствующие файлы:
   - [Scalping_SMA_1.15.2_parity_metrics.pine](../tools/pine_reference/generated/Scalping_SMA_1.15.2_parity_metrics.pine) — 45 показателей, включая Formation, Execution, Geometry, Context, Exhaustion, MAE, AVG, Continuation, BTC Shock, уровни и состояния;
   - [Scalping_SMA_1.15.2_parity_signals.pine](../tools/pine_reference/generated/Scalping_SMA_1.15.2_parity_signals.pine) — 26 сигналов.
3. Сохраните и добавьте **оба индикатора на один график**. Их названия оканчиваются на `PARITY metrics` и `PARITY signals`. Если лимит тарифа мешает, освободите место на отдельном тестовом графике.
4. Установите одинаковые inputs в обеих копиях. Для первого прогона удобно оставить значения по умолчанию и написать «все настройки по умолчанию». При изменённых настройках приложите перечень изменений. Отдельно укажите выбранные источники `lazyExternalSource`, `oiExternalSource`, `cvdExternalSource`, особенно если это выходы другого индикатора.
5. Прокрутите график влево, чтобы загрузить нужную историю; дождитесь расчёта обоих индикаторов. Затем в верхнем меню графика выберите **Download chart data / Скачать данные графика**, включив данные индикаторов, если интерфейс предлагает такой выбор. CSV должен содержать колонки `PARITY_formation`, `PARITY_execution`, `PARITY_avg_setup` и остальные `PARITY_*`.
6. Сохраните один общий CSV в `C:\dev\brokeweb\tradingview_data\full_reference\`. Сообщите имя файла, символ, таймфрейм и настройки. Переписывать значения из таблицы вручную не нужно.

TradingView официально поддерживает [экспорт данных графика и индикаторов в CSV](https://www.tradingview.com/support/solutions/43000537255-how-to-export-chart-data/). Копии публикуют численные ряды через `plot(..., display.data_window)`; такие ряды доступны для экспорта согласно [описанию визуальных выходов Pine](https://www.tradingview.com/pine-script-docs/visuals/overview/). Отсутствие линий на самом графике ожидаемо.

Каждая копия также выводит шесть колонок `PARITY_META_metrics_*` или `PARITY_META_signals_*`: начало загруженной истории, индекс свечи, шаг цены, признак закрытия, объём и длительность таймфрейма. Разные префиксы позволяют экспортировать обе копии вместе. Сверка потребует совпадения истории и inputs; последнюю незакрытую свечу нельзя считать историческим reference.

Если тариф допускает только одну копию за раз, выгрузите два CSV с одинаковой историей и настройками, лучше после закрытия проверяемого диапазона. Отдельные выгрузки могут различаться текущей свечой; инструмент объединения отклоняет конфликтующие значения, а не выбирает одно из них.

## 2. Intrabar: CSV журнала оповещений

Intrabar-reference — последовательность вычислений индикатора **внутри ещё открытой свечи**. Обычный исторический CSV не позволяет восстановить её задним числом: Pine исполняется на обновлениях realtime-свечи, а исторические свечи содержат итоговые данные. См. [модель исполнения Pine](https://www.tradingview.com/pine-script-docs/language/execution-model/).

1. Создайте третий личный индикатор из [Scalping_SMA_1.15.2_parity_intrabar.pine](../tools/pine_reference/generated/Scalping_SMA_1.15.2_parity_intrabar.pine), сохраните и добавьте его на обычный график Bybit perpetual.
2. Для короткого первого сбора используйте `BYBIT:ETHFIUSDT.P`, **5 минут**, и оставьте запись на **15–20 минут**, чтобы получить несколько закрытий свечей. Для проверки прежнего таймфрейма 30 минут потребуется более длинная запись — примерно 60–90 минут.
3. Выставьте нужные inputs. В группе `PARITY capture` задайте уникальный `Capture label`, например `ETHFI-5m-20260921-01`.
4. Создайте оповещение. В поле условия выберите **Scalping_SMA 1.15.2 - PARITY intrabar**, затем **Any alert() function call / Любой вызов функции alert()**. Webhook, email и Telegram для этого способа не нужны. Лишние каналы уведомлений можно отключить.
5. Убедитесь, что в **Alerts Log / Журнале оповещений** появляются сообщения с началом `{"brokeweb_trace":1`. Первое сообщение отправляется при первом realtime-вычислении, следующие — при обновлении рынка не раньше чем через 20 секунд после предыдущего. При отсутствии обновлений отдельный таймер сообщение не отправляет.
6. После нескольких закрытых свечей дождитесь ещё одного сообщения журнала, затем остановите оповещение. В меню **журнала оповещений** выберите экспорт CSV. Нужен файл с полным текстом **Message / Сообщение**, а не повторная выгрузка графика.
7. Положите CSV в `C:\dev\brokeweb\tradingview_data\intrabar\` и сообщите имя файла. Не пересохраняйте сообщения через Excel: длинные JSON-строки должны остаться целыми.

TradingView подтверждает [экспорт Alerts Log в CSV](https://www.tradingview.com/support/solutions/43000691967-what-timezone-is-displayed-in-alerts/); время в этом экспорте — UTC. Импортёр использует миллисекундные timestamps внутри сообщений и не зависит от языка заголовков CSV или порядка строк.

Оповещение использует серверную копию скрипта и inputs на момент создания. После изменения кода, настроек, символа или таймфрейма создайте новое оповещение с новым capture label. Это поведение и ограничение частоты описаны в [FAQ TradingView об alerts](https://www.tradingview.com/pine-script-docs/faq/alerts/).

## Что записывается и какие есть ограничения

Каждое сообщение содержит пакет последовательных realtime-вычислений: OHLCV, 45 метрик, 26 сигналов в битовой маске, состояния свечи, порядковый номер обновления, источник Pine, символ, таймфрейм, начало истории и 298 inputs. Это вычисления Pine на потоке TradingView, а не обещание записать каждую биржевую сделку. Выбранные `input.source` и цвета автоматически не включаются; источники нужно указать отдельно.

Пакеты ограничены буфером 24 000 символов. При переполнении счётчик `dropped` явно отмечает потерянные вычисления. Сообщение длиннее 38 000 символов останавливает запись с ошибкой вместо отправки обрезанного reference. Это ниже [лимита alert()-сообщения 40 960 символов](https://www.tradingview.com/support/solutions/43000773947-alert-name-and-message-size-limits/). Интервал 20 секунд удерживает обычную отправку ниже ограничения 15 срабатываний за три минуты. Другие alert-вызовы исходного финального dispatch в диагностических копиях отсутствуют.

Импорт обнаруживает пропуски пакетов, переполнение, конфликтующие дубликаты, изменение metadata и неправильные значения. Совпадающие timestamps не склеиваются: два вычисления в одну миллисекунду сохраняются по `seq`. Начальная неполная свеча и неизвестный неотправленный хвост отмечаются явно. Отсутствие обнаруженных пропусков не доказывает, что запись охватывает всё нужное время.

Статус успешного импорта — `CAPTURE_IMPORTED`, а parity остаётся **UNVERIFIED**. Для сравнения нужны синхронизированный Python replay, такой же origin и внешние `request.*` контексты. Прямой запуск существующего comparator с `--realtime` на этом trace пока не является готовым процессом: его timestamp keys не различают несколько обновлений за одну миллисекунду. Импорт сохраняет такие данные для последующего сопоставления.

Pine Logs можно использовать для небольших ручных диагностик, но здесь предусмотрен документированный CSV-экспорт Alerts Log. Скриншот таблицы годится для отдельных значений, однако не заменяет intrabar-последовательность. Поднимать публичный webhook или открывать доступ к локальному Docker не требуется.

## Локальные команды для разработчика

Запускать из корня проекта; пользователь может просто положить файлы в указанные каталоги.

```bash
python3 -m tools.pine_reference.exporter

# Для двух раздельных CSV; общий CSV повторно объединять не требуется:
python3 -m tools.pine_reference.merge metrics.csv signals.csv --output artifacts/local/reference.csv

# Для журнала оповещений; каждый запуск пишет в новый каталог:
python3 -m tools.pine_reference.trace \
  --input tradingview_data/intrabar/alerts.csv \
  --output-dir artifacts/local/intrabar-import-001
```

Для каждой сессии создаются `reference.jsonl`, `metadata.json`, `report.json`. Существующие файлы сессий не перезаписываются. Повреждённый вход возвращает exit code 2; успешный импорт возвращает 0, даже если отчёт обнаружил пропуски — это успех импорта, не подтверждение полноты.
