# Market data and Pine compatibility

The baseline uses exchange-native Bybit USDT linear perpetual OHLCV. The universe is downloaded from every instruments-info page and filtered to Trading, LinearPerpetual, USDT quote, excluding pre-listings. Refresh the whole universe periodically; the WebSocket manager supports adding and removing subscriptions. No static coin universe is bundled. Metadata retains exchange tick size, base and quote coins, status, launch time, and contract type. See [Bybit instruments API](https://bybit-exchange.github.io/docs/v5/market/instrument).

`backend.marketdata.BybitAdapter` exposes async `instruments()`, `klines(symbol,timeframe,limit,end,start)`, `backfill(symbol,timeframe,count,end)`, `tickers()`, `open_interest(...)`, and `close()`. Pass an `httpx.AsyncClient` to inject a transport in tests; otherwise the adapter owns its client. HTTP failures and nonzero exchange return codes remain errors. Retry only transient network/server/rate-limit failures, with bounded backoff. Backfill pages move backwards using the earliest open timestamp minus one millisecond, deduplicate, and return chronological bars. History can be shorter than requested for new instruments; missing bars are not synthesized. See [Bybit klines](https://bybit-exchange.github.io/docs/v5/market/kline).

`Bar` timestamps are UTC milliseconds, with an exclusive `end`. Bybit inclusive WebSocket ends and Binance inclusive REST close times are converted once at ingestion. Closed status for REST uses exchange server time. All market price/volume data retains the original float values without rounding entire series to tick size. Decimal tick rounding is available where Pine explicitly requires it.

`BinanceBtcContextAdapter` supplies Binance USD-M Futures BTCUSDT perpetual OHLCV through `/fapi/v1/klines`, plus its exchange metadata. It never substitutes Bybit BTC. The engine calculates the Pine EMA/regime/shock in each requested context from these bars. See [Binance futures klines](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/market-data/rest-api/Kline-Candlestick-Data).

## Realtime and 30-second candles

`BybitWebSocketManager(callback)` manages independent connection shards, automatic reconnect, ping heartbeat, receive timeout, and incremental subscribe/unsubscribe on existing sockets. Stable shard assignments preserve existing feeds while new symbols are added; additional sockets open only when capacity requires them. `update_subscriptions(symbols,timeframes,full_realtime)` takes a set of symbols selected for public trades. The callback receives `kline`, `trade`, or `health` events. Reconnection health events identify affected topics; the consumer must reconcile native candle gaps before resuming alerts. Feed errors are surfaced instead of silently reducing coverage. See [Bybit connections](https://bybit-exchange.github.io/docs/v5/ws/connect) and [kline stream](https://bybit-exchange.github.io/docs/v5/websocket/public/kline).

`TradeAggregator(symbol)` builds 30S candles from the `T` exchange timestamp and deduplicates by trade `i`. Open and close use chronological exchange timestamps; high, low, base volume and notional sum use all accepted trades. At equal milliseconds the exchange delivery order determines open/close order. The [public trade protocol](https://bybit-exchange.github.io/docs/v5/websocket/public/trade) supplies these fields. Bars align to UTC multiples of 30,000 ms. A configurable lateness watermark delays confirmation. Late trades for committed buckets are rejected and recorded as gaps requiring review/replay; they never mutate already committed calculations silently.

The first bucket after connection/reconnection is incomplete. `flush(exchange_time)` returns `(Bar, complete)` pairs. Empty intervals are absent, not fabricated flat candles. Checkpoints preserve recent trade IDs and bars, but restore invalidates continuity because process downtime cannot establish coverage. Bybit REST klines cannot reconstruct historical 30S trade distribution. Consequently chart 1m using micro 30S remains DEGRADED until its required trade-derived warmup actually exists. A full backfill of ordinary minute bars does not solve this limitation.

`alignment.quality()` returns FULL_REALTIME, KLINE_REALTIME, or DEGRADED with reasons. No-trade-feed quality is explicitly DEGRADED for charts requiring 30S. Feed staleness and history gaps also degrade it. `BarBuffer` prevents delayed partial frames replacing confirmed candles and supports authoritative REST correction. `reconcile_micro()` compares a complete set of 30S candles against the native closed candle and returns MATCH/MISMATCH/INCOMPLETE and replay requirement; it cannot repair unknown individual 30S candles. A caller must replay corrected native bars before enabling alerts.

## Timeframe and volume semantics

Pine timeframe strings use minute numbers and `S`, `D`, `W`, `M` suffixes. UTC week boundaries start Monday; calendar month boundaries account for variable month length. Exchange-native intervals are validated rather than sent as invalid requests. Auto micro profiles are `<=1m:30S`, `<=5m:1m`, `<=15m:5m`, `<=1h:5m`, `<=4h:30m`, otherwise `1h`.

Historical `security_bar(...,realtime=False)` selects the last confirmed context value available at the chart close. Realtime can use a developing HTF candle. `lower_tf_bars()` returns actual intrabars belonging to the chart interval. Engine expression evaluation must happen inside the requested context; selecting a bar alone does not reproduce a context's EMA history.

Native Bybit `turnover` and ticker `turnover24h` are metadata. The baseline Pine fixed-hour notional uses `volume * (high + low + close) / 3` for base-volume feeds, direct volume for quote-volume feeds, and NA for unsupported tick-volume feeds. The sum uses 24 hourly observations. Hourly returns and ATR-derived NATR similarly must be calculated from hourly OHLCV, never ticker percentage fields. Pine source functions and calculation order remain authoritative.

## Optional external sources

`open_interest()` accesses the Bybit historical OI endpoint independently. Trade-derived CVD is explicitly versioned `bybit-taker-base-volume-v1`, a running signed base volume (Buy positive, Sell negative). It is not assumed equivalent to an arbitrary TradingView external CVD input. OI/CVD must not enter baseline scoring unless the exact optional inputs are enabled and source equivalence is verified. DOM is outside baseline parity.

## Numerical verification and remaining evidence

`backend.engine.pine_compat` implements NA/nz, history offsets, SMA, EMA, Wilder RMA/ATR, extrema and offsets, pivots, sum, crossings, barssince, valuewhen, change, HLC3, clamp and tick rounding. Inputs are chronological lists; scalar functions return the current value. SMA/sum collect non-NA observations; extrema use a fixed bar window. EMA seeds from the first valid observation; RMA uses an SMA seed. Pivot plateaus select the rightmost equal extreme, confirmed after the right strength. See the [Pine reference](https://www.tradingview.com/pine-script-reference/v6/) and [TradingView function FAQ](https://www.tradingview.com/pine-script-docs/faq/functions/).

Unit tests use analytical sequences and mocked exchange protocol payloads. They cover NA/seed semantics, gap true range, pivot plateau/delay, tick half ties, calendar alignment, pagination, exchange errors, trade deduplication, reconnect/restart gaps, native reconciliation, and dynamic WebSocket removal. These tests are not external TradingView reference data. EMA/RMA initialization, pivots with missing samples, feed differences, and intrabar timing still need the parity export before any VERIFIED claim.

A direct public-feed smoke check on 2026-09-14 retrieved 761 eligible Bybit instruments and three native 1m bars for the first discovered instrument, plus three Binance BTCUSDT perpetual 1m bars. This is a connectivity observation, not a guarantee of future availability or indicator parity.

## Binance realtime context (2026-09-15)

`backend/marketdata/binance_websocket.py` consumes native BTCUSDT futures klines for every requested context TF. The routed URL is `wss://fstream.binance.com/market/stream?streams=…`. Binance documents the routed market endpoint and combined-message wrapper in [Websocket Market Streams](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/Connect); the official [USD-M connector](https://github.com/binance/binance-connector-python/blob/master/clients/derivatives_trading_usds_futures/src/binance_sdk_derivatives_trading_usds_futures/websocket_streams/websocket_streams.py) describes native kline updates at 250 ms when available. This is exchange sampling, not a guarantee of identical TradingView ticks.

Reconnects trigger REST repair covering the elapsed gap, with chronological continuity validation. A slower REST open-bar response cannot replace a newer WS sample. Confirmed candles cannot be downgraded to open. Each BTC timeframe has its own freshness timestamp. If streaming context is unavailable, the snapshot explicitly reports `BINANCE_REST_FALLBACK` / DEGRADED and alert eligibility is suppressed. Bybit chart events remain the execution trigger; a BTC update alone does not create a synthetic chart tick.

A live test received both requested native 5m and 15m BTC updates in 0.53 seconds; evidence: `artifacts/local/binance-websocket.json`. No TradingView reference was involved.
